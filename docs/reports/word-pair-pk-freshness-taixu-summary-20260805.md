# 词对 PK 玩法升级 — 太虚五转综合总结

> 散怀 → 澄源 → 叩实 → 破妄 → 归真，2026-08-05 全程 29min，non_deterministic 策略路径

## 一句话结论

**第一波交付"手感+仪式+闭环"三件套：连击/音效/卡牌表情（D1）＋开局 3-2-1/每日挑战/随机事件卡（D3）＋弱点雷达/错词入库（D4）；第二波做抢答模式和 PWA 离线安装；Tauri 桌面版放在远期，且 TTS 必须走原生插件或预生成音频，不许依赖 WebView2 语音。** 在线 PK 与班级模式本轮淘汰，但其内核（抢答、赛后数据）已分别被吸收。

## 关键认知转折

1. **"无聊"病灶定位（hegel）**：配对游戏本身有实证学习效果（bayes P4 验证），无聊感不在机制而在表现层——8 对配完即止、无深度、无复玩钩子。所以不是推翻玩法，是给玩法加层次。
2. **特效与学习必须捆绑（bayes 修正）**：Duolingo 反方证据（1200 天连胜没学会西班牙语）揭示 gamification 保 retention 不保 learning。纯特效层上线会重蹈覆辙——D4 学习闭环从"加分项"升格为"必选项"。
3. **TTS 风险反转（feynman 否决修正）**：bayes 基于搜索判定"TTS 风险实质性解除"，但盲审指出项目自身 8/4 事故史（speechSynthesis cancel 永久哑+死锁）未被纳入验证。结论从"解除"修正为"硬前置"：Tauri 下 TTS 走 tauri-plugin-tts 或预生成音频，且本地版本在 WebView2 上必须做冒烟测试。
4. **完整性幻觉（feynman VETO-2）**：收敛时自认"无遗漏"，实际 27/66 想法没入簇。遗漏清单里躺着 37 PWA——D6 的 1/10 成本替代方案，差点被整个流程漏掉。防具：pipeline 产物交叉数账（本总结 §7 起引入）。

## feynman veto 处置（2 项技术否决，均已复核成立）

- **VETO-1（confidence 无区间）**：接受。最终结论弃用点估计排序，改为序数制（第一波/第二波/远期）+ 定性论证（证据强度 × 实现成本 × 架构风险）。
- **VETO-2（39/66 映射不完整）**：接受。27 个遗漏想法补齐归属：
  - 升入第二波：**49 心形生命值+连胜火焰**（D1 扩展，Duolingo 已验证）、**46 语音配对**（D5 扩展，练听力）、**50 单词图鉴收集**（D4 扩展，长线收集欲）
  - 升级为 D6 替代：**37 PWA 离线安装**——浏览器原生"安装到桌面"，零打包成本，speechSynthesis 与线上版同环境（无 WebView2 风险）
  - 其余 21 个（3,5,7,10,11,17,20,21,22,23,28,33,35,44,45,48,51,52,55,56,58,61,66 中的未升级项）入待选池，实施时按需取用
- **bayes TTS 取证修正**：D6 存活条件硬化为"TTS 必须走 tauri-plugin-tts 原生插件或预生成音频包；WebView2 冒烟测试为实施前置"。

## §5 debono 归真 — 被批判命题的最强存活论证

### 命题 A：Tauri 桌面版（D6，被降级为远期）

**最强存活论证**（策略：S2 条件缩窄 + S4 类比复活）：
桌面学习工具的忠实用户群真实存在——Anki 以极简桌面形态存活二十年，说明"本地、离线、双击即用"本身就是一种价值主张。本项目的 TTS 事故史是浏览器环境的伤疤，不是桌面形态的死刑：tauri-plugin-tts 用原生系统语音（Windows SAPI），绕开 WebView2 的 speechSynthesis 完全可行。词库 5254 词内嵌 + build.py 产物直接可打包，无服务端依赖。家长场景（担心孩子乱点网页/要全屏专注）只有桌面版接得住。

**存活条件**：
- TTS 经原生插件（tauri-plugin-tts）实现并冒烟通过 → 存活概率高
- 不满足：沿用 WebView2 speechSynthesis → 不成立（8/4 事故史 + 环境差异双重风险）
- 时间窗口：WebView2 runtime 在 Win10 1803+ 预装，目标机器无需额外安装

**概率量化**：P(原生插件 TTS 可用) ≈ 0.85（插件活跃维护）｜P(打包链路 1 天内跑通) ≈ 0.7（Tauri 2.x 成熟）→ 期望存活 ≈ 0.60

**四维价值扫描**：用户价值=离线离线还是离线，装一次不用开浏览器｜技术收益=复用 100% 现有构建产物｜团队成长=Tauri 能力线（用户另一项目 Cream 已用 Tauri 2.x）｜战略对齐=本地版→PWA→在线版的产品阶梯

### 命题 B：在线 PK（D7，被淘汰）

**最强存活论证**（策略：S3 时间延迟 + S5 反面代价法）：
双人 PK 的完整形态必然包括"不在同一台设备前"——同屏分边是物理约束的妥协。浏览器 WebRTC 数据通道 + 信令（免费公共 STUN/TURN）已可支撑 1v1 对战，无需自建服务器。当前淘汰理由（无后端架构被破坏）成立的前提是"本轮就要做"；把时间轴拉到 6-12 个月后，Tauri 版若存活，局域网直连（38）和 WebRTC 房间（25）反而是桌面版最自然的功能延伸。不做在线化的代价：游戏永远困在"面对面"场景，节假日异地 PK、睡前亲子连线全部失去。

**存活条件**：
- 前提：先有 PWA/桌面版底座（P(6 个月内) ≈ 0.4）
- WebRTC 1v1 状态同步复杂度可控（对局状态机本就单侧持有，同步成本低）
- 信令可用公共服务兜底，零运维

**概率量化**：P(底座就位) ≈ 0.4 × P(WebRTC 实现成功) ≈ 0.75 → 期望存活 ≈ 0.30

**四维价值扫描**：用户价值=异地 PK 场景解锁，双人游戏不再受物理距离约束｜技术收益=架构升级路径明确，不推翻单 HTML 内核｜团队成长=WebRTC 实战经验｜战略对齐=从"单机小游戏"走向"可联机产品"的分水岭

### 命题 C：班级模式（D8，被淘汰）

**最强存活论证**（策略：S1 逆向利益相关方）：
批判视角盯着"用户=学生"，但课堂场景里真正掌握采购权和部署权的是老师。Kahoot 的学期研究证明竞答对所有竞争偏好的学生都提升学习效果——班级模式不是伪需求，是"用户"定义错了。老师要的：开房、投屏、全班抢答、赛后数据。meme 反馈图（65）可以零成本先落地为失败动画，为将来班级模式埋体验种子。

**存活条件**：
- 学生端免登录（6 位房间码即身份）——本项目的"房间码"想法已具备雏形
- 老师端需要一个极简管理界面（这是真实增量成本，不回避）
- 时间窗口：产品先在学校/家庭场景跑出口碑，班级模式是"被要求的"而非"主动做的"

**概率量化**：P(口碑跑出) ≈ 0.35 × P(老师主动要求) ≈ 0.7 → 期望存活 ≈ 0.25

**四维价值扫描**：用户价值=课堂互动场景唯一解（同屏 PK 无法覆盖 40 人班级）｜技术收益=无｜团队成长=教育产品运营认知｜战略对齐=与"学习闭环"理念同源，是 D4 的放大版

### 命题 D：PWA 离线安装（37，曾被遗漏）

**最强存活论证**（策略：S2 条件缩窄）：
它是"桌面/离线"需求的最小实现：manifest + service worker 两个文件，浏览器原生支持"安装到桌面/任务栏"，与线上版共享同一套 speechSynthesis 环境——**没有 WebView2 风险**。D6 的所有核心价值（离线、图标、全屏、一键启动）它都提供，唯一缺的是"独立安装包"这一形式。

**存活条件**：项目部署在 HTTPS（Vercel 已满足）｜service worker 缓存策略与 build.py 版本号机制兼容（revision 变化即更新缓存）

**概率量化**：P(实现成本 < 1 天) ≈ 0.9 → 期望存活 ≈ 0.75（本批最高）

**四维价值扫描**：用户价值=手机/电脑"装到桌面"，仪式感与可达性双升｜技术收益=几乎为零风险增量｜团队成长=SW 缓存模式经验｜战略对齐=Tauri 远期的自然垫脚石

**归真小结**：被淘汰的不是"没价值"，是"时机未到"。本轮的实际边界是：**先做浏览器内能验证的一切（D1/D3/D4/D2-PWA），把需要新形态支撑的（Tauri 联机、班级）留作阶梯上层**。D7/D8/Tauri 全部获得存活条件与唤醒信号，价值未被浪费。
